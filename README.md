# CFB Pick'em

A college football pick'em for a group of friends. No accounts, no logins —
open the link, pick a name once, make your picks.

- **Page**: static HTML/CSS/JS, hosted on GitHub Pages
- **Picks**: stored in Supabase, shared by everyone
- **Games and scores**: `slate.json`, committed here once a week

## Files

| File | What it is |
|---|---|
| `index.html` | The page |
| `app.js` | The whole app (built — see below) |
| `styles.css` | Styles |
| `config.js` | Your Supabase URL and public key |
| `slate.json` | Every week's games, lines and final scores |
| `parts/`, `build_app.py` | Source pieces `app.js` is assembled from |

`app.js` is generated by `python3 build_app.py`. Edit the files in `parts/`
and rebuild rather than editing `app.js` directly.

## Setup

1. Create a Supabase project and run the SQL in **Database schema** below.
2. Put your project URL and **anon/public** key into `config.js`.
3. Push this folder to a public GitHub repo.
4. Repo **Settings → Pages → Source: Deploy from a branch**, branch `main`, folder `/ (root)`.
5. Wait a minute, then open `https://<you>.github.io/<repo>/`.

The anon key belongs in `config.js` and is safe to commit — it's designed to
ship in client-side code, and the row-level security policies are what protect
the data. Never put the `service_role` key here.

## Database schema

```sql
create table picks (
  season      int  not null,
  week        int  not null,
  player_id   text not null,
  player_name text not null,
  picks       jsonb not null default '{}'::jsonb,
  super_dog   jsonb,
  mortal      jsonb,
  updated_at  timestamptz not null default now(),
  primary key (season, week, player_id)
);

alter table picks enable row level security;
create policy "read picks"   on picks for select using (true);
create policy "write picks"  on picks for insert with check (true);
create policy "update picks" on picks for update using (true) with check (true);
```

**Known tradeoff:** with no login there's no identity to check against, so any
visitor can technically overwrite any row. Fine for a private link among
friends; don't post the link publicly.

## slate.json

```jsonc
{
  "season": 2026,
  "currentWeek": 4,
  "weeks": {
    "4": {
      "games": [
        {
          "id": "g1",
          "away": "MIA", "home": "WAKE",     // keys into TEAMS in app.js
          "awayRank": 5, "homeRank": null,   // AP rank or null
          "kickoff": "2026-09-18T23:30:00Z", // ISO-8601 UTC
          "spread": 20.5,                    // the HOME line; negative = home favoured
          "total": 55.5,
          "network": "ACCN",                 // optional
          "note": "Line estimated"           // optional; shows as a warning on the card
        }
      ],
      "results": {
        "g1": {"a": 21, "h": 28, "a1": 7, "h1": 14}  // finals + halftime; a1/h1 optional
      }
    }
  }
}
```

Picks lock automatically at each game's `kickoff`. A week is graded as soon as
its `results` appear — the page does the scoring, so the weekly job only has to
supply raw scores.

Only `currentWeek` is open for picking. Past weeks stay in `weeks` so the
season leaderboard can total them up.

## Scoring

| | |
|---|---|
| Standard pick | 1 point correct, 0.5 on a push |
| Super Dog (a +4.5 or bigger underdog) | 5 for a cover, 5 + the spread for an outright win, 1 on a push |
| Mortal (buy 6 points on any spread or total) | 1 point correct, 0.5 on a push |

1H spreads, 1H totals and team totals are **derived** from the full-game spread
and total (`deriveLines` in `parts/`), since books don't publish them for every
game. They're the same number for everyone but aren't real book lines.

## Weekly update

A scheduled task commits a new `slate.json` every Saturday morning: it adds the
finished week's `results`, appends the new week's `games`, and bumps
`currentWeek`. Players' rows are keyed by week, so nothing needs clearing.

To do it by hand: edit `slate.json`, commit, done. The page cache-busts the
fetch, so a reload picks it up.

## Local development

```bash
python3 build_app.py      # rebuild app.js from parts/
python3 -m http.server 8000
```

`config.js` needs a real Supabase URL and key, or the page runs in local-only
mode and says so at the bottom of the screen.
